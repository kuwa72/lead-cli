# RFC: 受信箱の高密度 UI・配色仕様

- **Issue**: [#123](https://github.com/kuwa72/lead-cli/issues/123)
- **親・関連**: [#90](https://github.com/kuwa72/lead-cli/issues/90)（受信箱 UX 移行） / [#121](https://github.com/kuwa72/lead-cli/issues/121)（詳細プレビュー分割）
- **ステータス**: 実装仕様。UI 実装・実機検証は未完了
- **更新日**: 2026-09-10
- **参考スキル**: `.devin/skills/tui-design` / `.devin/skills/ui-craft` / `.claude/skills/ui-craft-dense-dashboard`

## 1. 一覧と判断材料を並べ、Issue 承認へ直結させる

`lead inbox` は、左に高密度一覧、右に選択追従プレビューを表示する。操作者が「何を承認するか」「どの Issue に一言返すか」を判断するための画面とする。

2026-09-10 のユーザー指示により、[rfc-inbox-ux.md](rfc-inbox-ux.md) の「分割ペインは作らない」は本画面には適用しない。Issue 承認を人間のゲートとする点は維持する。PR のレビューや最近マージの既読化を追加のゲートにしない。安全装置・CI・規約ファイル保護は変更対象外とする。

本仕様は旧案の「80 列以上で左右分割」「狭い端末では下部プレビュー」「配色は未決」を置き換える。ライブのエージェント画面は常設せず、`p` から開く。競合調査 RFC の古いマルチペイン運用をそのまま復活させるものではない。

設計値は CRAFT=7、MOTION=3、DENSITY=9、VARIANCE=4。特徴は選択行の `>` とプレビューの Issue 番号を同じアクセントで対応させること。カード・グラフ・装飾用アイコンは追加しない。

## 2. ヘッダーとフッターを共有し、本文に高さを使う

以下は配置の説明用サンプルであり、実データや実機のキャプチャではない。列の実幅は §3 に従う。

```text
lead — kuwa72/lead-cli                                                   Running 3/3   Updated 12s ago
Review 2   Blocked 1   Merged 5   Running 3
────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
   Issue Title                             Updated Agent   Tries     PR│ #123  Review
  ▾ Review (2)                                                         │ Warn when stock is zero
>   #123 Warn when stock is zero                3m claude      1      -│
    #124 Add approval transition                8m claude      1      -│ Purpose · Issue
  ▾ Blocked (1)                                                        │ Prevent orders with no stock.
     #88 Stabilize finish tests                25m claude      3   #456│
  ▸ Merged (5)                                                         │ Acceptance criteria · Issue
  ▸ Running (3)                                                        │ [ ] Show a warning at zero stock
                                                                       │ [ ] Keep the order unchanged
                                                                       │ [ ] Test the boundary condition
                                                                       │
                                                                       │ Enter: Full details
────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
#123 · Ready for approval
[Enter] Open   [a] Approve   [t] Reply   [?] Help   [q] Quit
```

| 領域 | 高さ | 内容 |
|---|---:|---|
| ヘッダー | 1 行 | リポジトリ、実行中数／上限、最終取得からの時間 |
| サマリ | 1 行 | Review / Blocked / Merged / Running の件数 |
| 上部区切り | 1 行 | 全幅の水平線 |
| 列見出し | 1 行 | 左は列名、右はプレビューの Issue 番号と状態 |
| 本文 | `高さ - 7` 行 | 左は一覧、右はプレビュー |
| 下部区切り | 1 行 | 全幅の水平線 |
| フィードバック | 1 行 | 対象番号、操作中・成功・エラー。平常時も高さを予約 |
| フッター | 1 行 | 文脈に応じた最大 5 操作 |

外枠は設けない。左右の境界線は列見出しと本文の範囲に 1 本だけ引く。右ペインには左端 1 セルの内余白を設け、内容幅を右幅から 1 セル引いた値にする。サマリは全体の件数、区画見出しは一覧内の位置を示す。サマリをタブ・フィルター・ボタンとして扱わない。

ヘッダーは右側の稼働数と更新時刻を確保し、長いリポジトリ名を `…` で省略する。フィードバックも 1 行に収め、詳細なエラーは別画面で全文を読めるようにする。横幅の計算にはバイト数や rune 数ではなく、ANSI を除いた表示セル幅を使う。

本文は残りの高さを使い、24 行端末では 17 行となる。長い一覧は本文内でスクロールする。区画見出しが画面外へ出るときは現在区画の見出しを本文先頭に固定し、二重に描画しない。ヘッダーとフッターはスクロールしない。

### 2.1 幅が足りないときはプレビューを隠す

| 端末サイズ | 表示 |
|---|---|
| 幅 120 以上、高さ 24 以上 | 左右分割 |
| 幅 80〜119、高さ 24 以上 | 全幅一覧。`Enter` で全画面詳細 |
| 幅 80 未満、または高さ 24 未満 | `Terminal too small. Resize to 80x24. [q] Quit`。表示可能な幅で折り返す |

分割時は `左幅 = floor((端末幅 - 1) × 0.60)`、`右幅 = 端末幅 - 1 - 左幅` とする。120 列で左 71、境界 1、右 48 セルになる。全幅一覧では端末幅をすべて左幅に使う。狭い画面の下部プレビューは採用しない。

リサイズしても選択番号・折り畳み状態・詳細の閲覧位置を保持する。最小サイズ未満では状態変更キーを受け付けず、サイズ復帰時に再開する。端末の終了シグナルは妨げない。

## 3. 一覧は固定列、詳細は原文を使う

区画順は `Review → Blocked → Merged → Running`。Review と Blocked は初期展開、Merged と Running は初期折り畳みとする。空区画も件数 0 の見出しを残す。1 Issue は 1 行、行間と区画間の空行は 0 とする。

| 列 | 幅・配置 | 内容 |
|---|---|---|
| 選択 | 2 セル | `> ` または空白 2 個 |
| Issue | 最小 6 セル、右揃え | `#123`。番号を省略しない |
| Title | 残余幅、左揃え | 最小 20 セル。末尾を `…` で省略 |
| Updated | 7 セル、右揃え | Issue の更新からの相対時間。`12s` / `3m` / `2h` / `1d` |
| Agent | 7 セル、左揃え | 長い名前は省略し、詳細で全文を示す |
| Tries | 最小 5 セル、右揃え | `Attempts` の値。リトライ回数への読み替えや減算をしない |
| PR | 最小 6 セル、右揃え | `#456`。番号を省略しない |

選択列を除く隣接列の間は 1 セル。最小幅の合計はタイトル以外が 38 セルとなり、左幅 71 ではタイトルに 33 セルを使える。数値列は取得した一覧全体の桁数に合わせて拡張し、選択移動では幅を変えない。タイトル幅 20 を確保できない場合は `Updated → Agent → Tries → PR` の順に列を隠す。隠した情報は詳細で閲覧できる。

状態は区画名で示し、全行に同じ状態ラベルを繰り返さない。値が存在しない、または不明な場合は `-`。既知の 0 と不明値を区別する。PID・ブランチ・ログパス・ペイン ID は詳細へ移す。

ヘッダーの `Updated … ago` は一覧の最終成功取得時刻、行の `Updated` は Issue 自体の更新時刻。ヘルプでこの違いを説明する。相対時間だけで判断できないときのため、詳細には元の UTC 時刻も表示する。取得上限がある件数は `20+` などで下限と分かるように表示し、総数と偽らない。

### 3.1 プレビューの冒頭は区画に合わせる

| 区画 | 先に見せる情報 | 続く情報 |
|---|---|---|
| Review | 目的、受入条件 | Issue 本文、コメント |
| Blocked | 記録された停止理由、関連する直近コメント | 試行回数、PR、実行情報 |
| Merged | PR の受入条件チェックリスト | Issue 本文、マージ情報 |
| Running | エージェント、試行回数、関連 PR | Issue の目的、実行情報 |

プレビューの共通ヘッダーには番号・状態・完全なタイトルを置く。本文の見出しやチェックリストを原文から抽出し、`Issue` / `PR #456` / `Comment` の出典を付ける。抽出できなければ本文の冒頭を表示する。停止理由や進捗率をタイトル・試行回数から推測しない。

プレビューは表示専用で、独立したフォーカス・スクロール操作・編集機能を持たない。長文は利用可能な高さで切り、末尾に `Enter: Full details` を表示する。全画面詳細では本文・コメント・PR 本文・実行情報のすべてをスクロールして読める。PR がない場合は `No linked PR`、PR 本文の取得失敗時は `PR details unavailable` と区別する。

### 3.2 現行モデルにないデータは取得経路を追加する

現行 `internal/inbox/sections.go` の `Item` は `MergedAt` を持つが、Issue 更新時刻や停止理由は持たない。`internal/ports/ports.go` の `Issue` は番号・タイトル・本文・状態を持ち、コメントは含まない。

- `Updated` 列には Issue 更新時刻の取得・受け渡しを追加する。`MergedAt` や取得時刻で代用しない。
- コメントと停止理由は GitHub の記録から取得する。構造化した停止理由がない場合は原文コメントとして表示する。
- 追加情報を取得できなくても一覧全体を失敗扱いにせず、その情報だけ不明・取得失敗と表示する。

## 4. 既存キーを維持し、文脈で主操作を変える

| キー | 動作 |
|---|---|
| `j/k` / `↑/↓` | 一覧の選択移動。プレビューが追従 |
| `Enter` | Issue 行は全画面詳細。区画見出しは開閉 |
| `Space` / `→` / `l` | 区画見出しの開閉 |
| `z` / `Tab` | 全区画の開閉。ペインのフォーカス切替に転用しない |
| `a` | Review の Issue を承認 |
| `e` | Review の Issue を編集して承認 |
| `x` | 対象 Issue を却下。対象番号と close することを示し、確認入力で確定 |
| `t` | 一言返す。コメント送信と AI 再走の成否は別々に表示 |
| `p` | 利用可能なエージェント画面／ログを開く |
| `n` | 不具合を報告し、関連する追い Issue を起票 |
| `c` | Merged を既読化。実装 AI の進行には影響しない |
| `o` | ブラウザで開く |
| `s` / `r` / `R` | 新規起票 / 規約編集 / 再取得 |
| `?` | 現在の文脈の操作一覧 |
| `Esc` / `q` | 詳細・ヘルプから戻る。一覧の `q` は終了 |

全画面詳細では `j/k`・矢印・`PageUp/PageDown` でスクロールする。`Esc` / `q` で一覧の元の選択・スクロール位置へ戻る。本文入力中は文字キーをショートカットとして解釈しない。外部エディタや `p` の実行中は外部コマンドに端末を明け渡し、復帰後に再描画する。外部コマンド内のキーを inbox が横取りしない。

| 選択対象 | フッターの 5 操作 |
|---|---|
| Review | `[Enter] Open [a] Approve [t] Reply [?] Help [q] Quit` |
| Blocked | `[Enter] Open [t] Reply [p] Peek [?] Help [q] Quit` |
| Merged | `[Enter] Open [n] Report bug [c] Mark seen [?] Help [q] Quit` |
| Running | `[Enter] Open [p] Peek [o] Browser [?] Help [q] Quit` |
| 区画見出し | `[Enter] Toggle [z] Toggle all [s] New [?] Help [q] Quit` |
| 全画面詳細 | `[↑/↓] Scroll [PgUp/PgDn] Page [o] Browser [?] Help [Esc] Back` |

フッターにない既存操作は `?` に残す。実行不能な操作はフッターから除き、ヘルプには理由付きで表示する。入力・確認中のフッターは `[Enter] Send` または `[Enter] Reject` と `[Esc] Cancel` に置き換える。

## 5. 非同期更新で対象を取り違えない

選択表示は即時に更新し、本文の取得開始は 150ms の選択安定後とする。同じ Issue のキャッシュがあれば先に表示できる。選択が変わるたびにリクエスト識別子を更新し、現在の選択番号・識別子と一致しない応答は破棄する。別 Issue の古い本文を新しい番号の下に残さない。

一覧の再取得時は Issue 番号で選択を保持する。対象が一覧から消えた場合は同区画の次の行、なければ前の行、空区画なら見出しを選択する。区画見出しを選択中はプレビューを空にし、以前の Issue の操作を受け付けない。

承認などの対象番号はキーを押した時点で固定する。同一対象への状態変更は処理中に重複送信しない。サーバー成功応答前に承認済みと表示しない。承認直前に取得した状態・本文が閲覧時点と異なる場合は更新内容を表示し、`Issue changed. Review before approving.` として承認を保留する。これはクライアント側の競合検出であり、GitHub API の原子的な比較更新を保証するものではない。

## 6. 空状態・失敗・操作結果を英語で区別する

| 状態 | コピーと挙動 |
|---|---|
| 初回取得 | `Loading inbox…`。未取得の件数は `-` |
| 本文取得 | `Loading #123…`。対象番号とタイトルは先に表示 |
| 再取得中 | 既存一覧を残し、ヘッダーに `Refreshing…` |
| 一覧取得失敗 | 既存一覧を残し `Stale · Last updated 2m ago`。初回失敗なら件数不明のまま `Unable to load inbox. [R] Retry` |
| 本文取得失敗 | プレビューだけに `Unable to load #123. [R] Retry`。`R` は一覧と現在の詳細を再取得 |
| 人間の作業なし | Review / Blocked がともに既知の 0 なら `No action needed`。Running / Merged は閲覧可能 |
| 承認中・成功 | `Approving #123…` → `Approved #123` |
| コメント成功 | `Commented on #123`。再走確認前に `Restarted` と表示しない |
| 却下成功 | `Rejected #123` |
| 既読化成功 | `Marked #123 as seen` |
| 操作失敗 | `Error: Could not approve #123. …`。対象・失敗内容・可能な回復操作を示す |

成功メッセージは 5 秒後に通常の選択説明へ戻す。エラーは再試行成功か明示的な解消まで残し、詳細説明が必要ならヘルプまたは詳細で全文を読めるようにする。通信失敗を `No action needed` と扱わない。

`e` のヘルプは `Edit & approve`、`c` は `Mark seen` とし、実際の副作用を隠さない。UI が生成する文言は英語、Issue 本文・タイトル・コメントは原文の言語を保持する。

## 7. 配色は青緑の選択色と中立色を基調にする

本文の大部分は中立色とする。青緑は選択と主操作の対応を示すアクセント、琥珀は注意、赤は失敗、緑は成功、青は処理情報に割り当てる。Review を警告色、Running の上限到達をエラー色にはしない。稼働率が高いだけでは異常ではない。

端末のフォント・文字サイズは変更しない。太字以外のウェイト、Web の `tabular-nums`、px 単位の余白、透明度、影、グラデーションは使わない。文字セル幅で配置し、背景色は空白セルにも明示する。RGB 値は sRGB の不透明色であり、端末背景との合成を前提にしない。

### 7.1 テーマを選ぶ契約

`LEAD_THEME` を inbox のテーマ指定用環境変数として追加する。以下は実装すべき仕様であり、現行 CLI で利用可能であることを示さない。

| 値 | 動作 |
|---|---|
| 未設定・空文字・`terminal` | 既定。端末の背景・前景色と ANSI 基本色を使う。背景は塗り替えない |
| `dark` | 暗い固定背景と Dark パレットを使う |
| `light` | 明るい固定背景と Light パレットを使う |

値は小文字の完全一致とし、その他の値は TUI 開始前に `Invalid LEAD_THEME: expected terminal, dark, or light.` と終了コード 2 で拒否する。独自色の任意指定、設定ファイル項目、実行中のテーマ切替、テーマ保存機能は今回追加しない。

背景色の自動推測や OSC による端末問い合わせは行わない。既定の端末追従を維持し、色の数値保証が必要な操作者が `dark` / `light` を明示する。固定テーマは inbox が描画する全セルを覆い、端末パレットや端末の既定背景設定自体は変更しない。

### 7.3 端末追従は ANSI 基本色だけで成立させる

| トークン・用途 | 端末追従時の表現 |
|---|---|
| canvas / surface | 端末既定背景。左右の違いは境界線で示す |
| primary / secondary | 端末既定前景。secondary に SGR dim を掛けない |
| emphasis | 端末既定前景＋太字 |
| 選択行 | 端末既定前景・背景に戻してから反転。全セルを同じスタイルにする |
| border.muted / border.strong | 端末既定前景。細い線で区切り、色で操作可能性を示さない |
| accent.primary | ANSI cyan、色番号 6、前景 SGR 36 |
| status.info | ANSI blue、色番号 4、前景 SGR 34 |
| status.warning | ANSI yellow、色番号 3、前景 SGR 33 |
| status.error | ANSI red、色番号 1、前景 SGR 31 |
| status.success | ANSI green、色番号 2、前景 SGR 32 |

端末追従では RGB / 256 色対応端末でもこの対応を使う。利用者がパレットを変更できるため、固定のコントラスト値は保証しない。選択記号、状態ラベル、太字、反転は色と独立して残す。

### 7.4 色能力と無着色の優先順位

テーマ値を検証した後、以下の順で描画モードを決める。

1. 非 TTY 出力、headless 出力、または `TERM=dumb` は plain。SGR・OSC・カーソル制御を一切出力しない。対話 UI に必要な TTY がなければ開始せず、headless 経路は通常テキストを返す。
2. `NO_COLOR` が空文字でない場合は monochrome。`NO_COLOR=0` も無着色とし、空文字は未指定と同じ扱いにする。`LEAD_THEME` や色能力より優先する。
3. `terminal` は §7.3 の ANSI 表現とする。
4. `dark` / `light` で `COLORTERM=truecolor` または `24bit` があれば RGB。なければ `TERM` に `256color` を含む場合は 256 色とする。
5. それ以外は固定パレットを使わず、端末追従 ANSI にフォールバックする。16 色環境に RGB の数値保証を持ち込まない。

monochrome は色指定を除去し、背景は端末既定にする。SGR の太字・反転は許可するが、dim・点滅は使わない。plain はそれらの装飾も除去し、`>` / `Review` / `Blocked` / `Error:` などの文字情報だけで判断できるようにする。ASCII が必要な経路では `▾` / `▸` / `─` / `│` / `…` を `v` / `>` / `-` / `|` / `...` に置き換えてから表示幅を計算する。

## 8. 選択・警告・本文の塗り分けを固定する

| コンポーネント | 前景・装飾 | 背景 |
|---|---|---|
| ヘッダーのリポジトリ | `fg.emphasis`＋太字 | `bg.canvas` |
| 稼働数・更新時刻・列見出し | `fg.secondary` | `bg.canvas` |
| サマリ・区画見出し | ラベルは `fg.primary`、件数は太字。Blocked が 1 以上ならそのラベルと件数のみ `status.warning` | `bg.canvas` |
| 通常行の番号・タイトル | `fg.primary` | `bg.canvas` |
| 通常行の時刻・Agent・Tries・PR | `fg.secondary`。PR に色付きバッジを付けない | `bg.canvas` |
| 選択行 | 全文 `fg.selection`。番号とタイトルは太字、左端 `>` のみ `accent.primary` | `bg.selection` |
| プレビューの Issue 番号 | `accent.primary`＋太字 | `bg.surface` |
| プレビューのタイトル・本文見出し | `fg.emphasis`＋太字 | `bg.surface` |
| プレビュー本文・コード | `fg.primary` | `bg.surface` |
| プレビューの出典・時刻・パス | `fg.secondary` | `bg.surface` |
| 本文リンク | `fg.primary`＋下線。大量のアクセントを作らない | `bg.surface` |
| 本文のチェックボックス | `[ ]` / `[x]` とも `fg.primary`。未チェックを警告扱いしない | `bg.surface` |
| 左右の境界線 | `border.strong` | `bg.canvas` |
| 上下の水平線 | `border.muted`。装飾用に限定 | `bg.canvas` |
| 通常のフィードバック | `fg.secondary` | `bg.canvas` |
| 処理中・成功・警告・失敗 | それぞれ `status.info` / `status.success` / `status.warning` / `status.error` と状態を示す文言 | `bg.canvas` |
| フッター | キーは太字、説明は `fg.primary`。文脈の主操作キー 1 個だけ `accent.primary` | `bg.canvas` |
| 入力・確認の対象番号 | `fg.emphasis`＋太字。エラーは入力欄の外で表示 | `bg.surface` |
| ヘルプ／全画面詳細 | 本文は `fg.primary`、見出しは `fg.emphasis`＋太字 | `bg.surface` |

主操作キーは Review で `a`、Blocked で `t`、Merged で `n`、Running で `p`、区画見出しで `Enter`、入力・確認中で `Enter` とする。全画面詳細とヘルプでは主操作の着色を省く。利用不能な主操作のために別のキーを勝手に着色しない。

通常画面のアクセントは選択記号・プレビュー番号・主操作キーの最大 3 箇所とする。意味色は状態が存在する箇所だけに使い、行全体や面積の大きい背景を赤・緑・琥珀で塗らない。Merged の全行を緑にしない。

### 8.1 スタイルの優先順位

入力・確認・ヘルプ表示中は、その画面だけがキーを受け付ける。一覧の選択番号は保持するが、背景側の反転・アクセント・主操作の着色を外す。全画面詳細は一覧を覆う。閉じたら元の選択スタイルを戻す。

選択行のスタイルは、行内の状態色・メタ情報色・下線・dim より優先する。Blocked の見出しを選択したときも全文を `fg.selection` にし、`Blocked` の文字は残す。RGB / 256 色では選択背景に SGR reverse を重ねない。端末追従／monochrome では反転を使い、選択行内の意味色・アクセントは無効にする。

警告・エラーは専用フィードバック行とプレビュー内のラベルに表示し、選択位置を奪わない。操作不可は灰色だけで示さず、ヘルプに `Unavailable: …` と理由を書く。

### 8.2 本文由来の装飾を制御する

Issue・PR・コメント・外部コマンドのエラー文に含まれる制御文字や ANSI / OSC シーケンスは、表示幅を計算する前に除去または可視文字に置換する。原文から端末色・ウィンドウタイトル・クリップボードを変更できないようにする。色は本仕様のレンダラーだけが付与する。装飾を終了したセルではスタイルを明示的に戻し、隣のペインや次行へ色を漏らさない。

## 9. 固定テーマはコントラストを数値で検証する

端末文字はすべて通常サイズの本文とみなす。本文・メタ情報・状態ラベル・選択記号は 4.5:1 以上、左右の構造境界線は隣接背景に対して 3:1 以上を満たす。背景色の差だけを選択の手掛かりにしない。上下の装飾線は 3:1 の対象外だが、文字・選択・操作の手掛かりには使わない。

2026-09-10 に sRGB 相対輝度で検算した結果を示す。256 色は指定した xterm パレットの RGB 値で計算し、自動近似値では検証しない。

| 組み合わせ | Dark RGB | Dark 256 | Light RGB | Light 256 |
|---|---:|---:|---:|---:|
| 本文／canvas | 14.64:1 | 14.69:1 | 14.84:1 | 13.04:1 |
| メタ情報／canvas | 8.13:1 | 8.04:1 | 5.74:1 | 5.26:1 |
| 選択文字／selection | 10.62:1 | 9.80:1 | 11.70:1 | 11.90:1 |
| 全文字の検証対象ペアの最小値 | 6.37:1 | 6.53:1 | 5.16:1 | 4.94:1 |
| 構造境界線／canvas・surface・selection の最小値 | 3.24:1 | 3.29:1 | 4.04:1 | 3.57:1 |

検証対象は各テーマ・色能力について次の 21 ペア、計 84 ペアとする。選択行が境界線に接する場合も含める。

- `fg.primary` / `fg.secondary` / `fg.emphasis` / `accent.primary` / 4 種の `status.*` と、canvas / surface の組み合わせ: 16 ペア、4.5:1 以上。
- `fg.selection` / `accent.primary` と selection の組み合わせ: 2 ペア、4.5:1 以上。
- `border.strong` と canvas / surface / selection の組み合わせ: 3 ペア、3:1 以上。

RGB の各成分を 0〜1 の sRGB 値 `c` に変換し、`c <= 0.04045` なら `c / 12.92`、それ以外は `((c + 0.055) / 1.055)^2.4` で線形化する。相対輝度は `L = 0.2126R + 0.7152G + 0.0722B`、比率は `(明るい L + 0.05) / (暗い L + 0.05)` とする。合否は丸める前の値で判定する。

ANSI の利用者定義パレット、端末の透明度・色補正、文字レンダリングはこの計算の対象外。数値検証は実機の読みやすさやスクリーンリーダー対応の検証を代替しない。

## 10. 動きより入力と表示の安定を優先する

選択・開閉・スクロール・リサイズ・画面切替のアニメーションは 0ms。色の補間、点滅、入口アニメーション、常時スピナーは使わない。処理中は固定位置のテキストを更新する。取得の 150ms 待機は通信制御であり、キー入力や選択表示は待たせない。

Bubble Tea の差分描画に乗せ、更新ごとに画面全消去しない。独立した描画ループや端末問い合わせを追加して TTY を奪い合わない。終了・外部コマンドへの受け渡し時は装飾・カーソル・端末モードを復元する。
